## 1. Failles critiques (CORRIGÉES)

### C1 — `finish_parent_registration` : énumération + usurpation d'enfant
`00053` avait re-passé la RPC à `authenticated` avec le **matricule séquentiel** (EC260001, EC260002… ~10⁴ valeurs/an, semi-public) comme **seule preuve d'identité**, sans garde d'abonnement ni plafond de demandes. Un attaquant obtenait un compte parent (voire **ACTIF** en auto-approbation) sur un enfant qui n'est pas le sien.
**Corrigé (00054)** : retour à `service_role` uniquement, preuve par **date de naissance** (modèle 00050), garde `school_is_writable` fail-closed, plafond 100 demandes EN_ATTENTE, message unique anti-oracle. Backend (`registerParent.js`) + formulaire parent mis à jour (champ date de naissance).

### C2 — `link_child` : rattachement par balayage de matricules
Un parent légitime pouvait tester les matricules et s'attribuer tous les enfants non rattachés de son école (puis lire notes, bulletins, paiements de ces enfants via les policies « branche parent »).
**Corrigé (00054)** : date de naissance en second facteur + rate limit DB (`sys_rate_limit` 10/h) + message générique. Frontend : champ date de naissance dans le rattachement (`ParentHome`).

### C3 — Policy `students_select_ecole` : scoping par rôle perdu
La vague 3 (00038) avait réécrit la policy **sans le périmètre par rôle** de 00029 : tout compte actif (élève, parent, enseignant) lisait les fiches de **tous** les élèves de l'école (matricules, dates de naissance, options) — ce qui rendait C1/C2 triviales et détruisait la preuve d'identité de 00050.
**Corrigé (00054)** : scoping 00029 restauré (direction/enseignants affectés/élève = soi/parent = ses enfants) + `school_is_readable` conservé.

## 3. Mineurs (CORRIGÉS)

- **Mojibake** (textes corrompus envoyés aux clients) : `adminFinances.js`, `adminSecurity.js`, `adminAudit.js` entièrement assainis (405, messages de purge, messages serveur, commentaires).
- **MFA verify** : clé de rate limit `req.ip` → `clientIp()` (cohérence multi-proxy).
- **ESLint en échec** (`prefer-const` `PlatformContext.tsx`) : corrigé.
- **`@ts-ignore` → `@ts-expect-error`** (`format.ts`, garde-fou rétabli).
- **`key={index}`** sur 2 listes (`StudentCsvImport.tsx`).
- **Script `lint` racine** : 10 fichiers récents de l'API non vérifiés (`adminMfa`, `totp`, `secretCrypto`, `timetables`, `delete-staff-account`…) — ajoutés.
- **`connect-src localhost` dans la CSP de production** : retiré (env par mode).
- Test RLS mis à jour (`link_child` nouvelle signature).
- Migration 00052 : contrainte `timetable_courses_time_order` désormais **VALIDATÉE**.

## 4. Constats NON corrigés (décisions / recommandations)

### 🔴 À traiter par le titulaire du compte (aucune modification de code possible)
1. **`.git-credentials` contient un token GitHub (`github_pat_…`) en clair**, dans un dossier synchronisé OneDrive. Le fichier est exclu de Git (jamais commité — vérifié dans tout l'historique), mais :
   - **Action 1 (obligatoire)** : révoquer ce token sur GitHub (Settings → Developer settings → PAT) et en générer un nouveau.
   - **Action 2** : remplacer le stockage par le Gestionnaire d'identifiants Windows (`git config --global credential.helper manager`) puis supprimer `.git-credentials`.
2. **`.env.local` (clé `service_role`) est stocké dans le dossier OneDrive** : le cloud est une copie du secret. Recommandé : rotation de la `service_role` (Supabase → API keys) puis déplacer les `.env` hors du répertoire synchronisé (ou chiffrer le coffre OneDrive).

### 🟠 Différées (architecturales, à planifier)
- **M-B12** : sessions MFA pré-auth et lockout login **en mémoire du processus** — incompatible avec ≥2 instances Render (à déplacer en base si scale-out).
- **M-B13** : contrôle anti-chevauchement enseignant dans les EDT : check-then-insert sans contrainte SQL (TOCTOU, exploitation limitée au directeur) → RPC transactionnelle ou contrainte d'exclusion.
- **M-F4** : double dérivation du statut d'abonnement (`db.ts mapSubscription` vs `utils/subscription.ts`) — règles ≤ 7 j divergentes entre composants ; à factoriser.
- **m-2** : `set_attendance` sans limite de rétroactivité (réécriture des présences de toute l'année) → suggérer `>= current_date - 30`.
- Typage : ~25 `any`/`catch (e: any)` restants (mappers `db.ts` notamment).

### ℹ️ Points positifs vérifiés
- Zéro XSS, zéro secret côté client, `target="_blank"` toujours protégés, export CSV durci contre l'injection de formules Excel.
- Backend : JWT toujours vérifié auprès de Supabase Auth, `school_id` jamais pris du client, statut ACTIF contrôlé, injections PostgREST neutralisées (`, ( ) \ % _`, tris whitelistés), mots de passe jamais renvoyés, secrets TOTP chiffrés AES-256-GCM.
- Base : RLS partout, `search_path` figé sur toutes les SECURITY DEFINER, TRUNCATE révoqué, CREATE révoqué sur `public`, fail-closed sur les tables internes.
- CI : actions épinglées par SHA, Supabase CLI figé, backend vérifié (`node --check` + `npm audit`), migrations appliquées via `db reset`.
- `npm audit` : **0 vulnérabilité** (front + backend).
